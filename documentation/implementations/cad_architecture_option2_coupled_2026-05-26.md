# Option 2: B-Rep Translation (Coupled Approach)

## Problem / Idea
Following the successful integration of OpenCASCADE (OCCT) for STEP import and robust boolean operations (Option 1), the next architectural step was to shift `CAD_OpenGL` from a polygon mesh editor to a true Boundary Representation (B-Rep) solid modeler. The goal was to embed OCCT topological shapes directly into the core geometry structures (`Solid`, `Face`, `Edge`, `Point`). The user explicitly chose a "coupled" approach, meaning the `CAD_OpenGL` structs directly hold `TopoDS_Shape` handles, accepting the potential compile-time impact in exchange for direct access and coding simplicity.

## Plan
1. **Update Core Geometry Structs**: Add `TopoDS_Shape`, `TopoDS_Face`, `TopoDS_Edge`, and `TopoDS_Vertex` to `Solid`, `Face`, `Edge`, and `Point` respectively.
2. **Create `OcctSurface` Wrapper**: Implement a new `Surface` subclass that wraps a `TopoDS_Face` and delegates `GetNormal(u, v)` to OCCT's `GeomLProp_SLProps`.
3. **Rewrite `STEPImport.cpp`**: Instead of creating a flat `Face` for every tessellated triangle, map the OCCT topology 1:1 to `CAD_OpenGL` topology. Create a single `Face` per `TopoDS_Face` and store the boundary loops.
4. **Update Renderer**: Modify `Patch::AddFace` and `Wireframe::AddEdge` to extract `Poly_Triangulation` and `Poly_Polygon3D` directly from the OCCT handles, bypassing the 2D projection and `earcut` logic for curved faces.

## Implementation Details & Bugs
- **CGAL Handle Conflict**: OCCT defines a `#define Handle(Class)` macro which conflicts with CGAL's `CGAL::Handle` class. Since the "coupled" approach means `Solid.hpp` includes OCCT headers, any CGAL file including `Solid.hpp` broke.
  - *Fix*: Added `#undef Handle` immediately before including CGAL headers in `StructureTriangulation.cpp`, `StructureCarve.cpp`, and `STLCgalPlanarExperiment.cpp`.
- **Scene::Clone**: Updated `Scene::Clone` to copy the OCCT handles (`occtVertex`, `occtEdge`, `occtFace`, `occtShape`) when duplicating geometry.
- **OCCT HashCode**: OCCT 7.9.3 provides `std::hash<TopoDS_Shape>` and `std::equal_to<TopoDS_Shape>` directly, so custom hash/equal structs were removed in favor of `std::unordered_map<TopoDS_Shape, Point*>`.

## Outcome
The migration was successful. `CAD_OpenGL` now natively holds B-Rep geometry. The renderer successfully extracts and displays the tessellation data generated by `BRepMesh_IncrementalMesh`. The application compiles and runs without crashing.

## Bugfix: Structure Carve failing with null prisms (2026-05-27)
**Problem:** The user reported that the Structure tool didn't seem to modify the solid when applied to `occt.stp`.
**Investigation:** We found that `StructureCarve::TryApplyStructureCarve` was failing silently because `BuildVerticalPrismOcct` returned a null shape. The root cause was that when converting `CAD_OpenGL` loops to OCCT wires, we were calling `w.Reverse()` on inner loops. However, `CAD_OpenGL` already stores inner loops with the correct orientation (CW relative to the CCW outer loop). Reversing them made the faces invalid, causing `BRepOffsetAPI_MakeOffset` to fail.
**Fix:** Removed `w.Reverse()` in both `StructureCarve.cpp` and `StructureTriangulation.cpp`. Additionally, simplified `StructureCarve.cpp` to pass the `currentUnion` compound directly to `BRepPrimAPI_MakePrism`, avoiding manual iteration and fusion of individual extruded faces.
